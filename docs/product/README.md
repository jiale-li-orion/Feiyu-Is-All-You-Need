# FatFish 产品设计

FatFish 先确立四条跨阶段保持稳定的设计约束，再按渐进式顺序展开各层设计。

## 设计法则

### 1. Attention-first

FatFish 的价值是替用户承担软件操作与信息管理成本。

任何界面元素都应该回答它能帮助用户获取什么信息、完成什么动作，或者避免什么判断负担。

这也约束大肥鱼的人格化表现：角色有价值，但不能妨碍日常工作。

### 2. Interaction before appearance

操作对象、反馈状态、导航与恢复行为先于视觉材质。

一个好看的 Sheet，如果拖动不跟手、返回后丢失阅读位置，就仍然是失败的交互设计。

### 3. Visual hierarchy follows information hierarchy

视觉焦点由任务和信息的重要性决定。

重要性可以通过留白、排版、位置和对比体现，而不需要反复添加颜色、阴影、卡片。

### 4. Progressive complexity

用户的界面逐层披露复杂度，设计过程也逐层引入新的约束。

每一层先收敛到可验证的判断，再开放下一层的设计自由度。

## 渐进式设计顺序

| 阶段 | 要解决的问题 | 主要产物 | 验收依据 |
|---|---|---|---|
| 1. 产品行为 | 用户究竟希望系统代替自己做什么 | 场景、目标、职责边界 | 是否减少实际操作和注意力成本 |
| 2. 信息架构 | 哪些信息应首先出现，怎样关联 | 页面拓扑、对象与信息层级 | 能否快速找到目标信息 |
| 3. 交互语义 | 操作如何触发、反馈、中断和恢复 | 页面操作路径、用户可感知的状态变化、反馈与恢复规则 | 行为是否可预期、可恢复 |
| 4. 组件与布局 | 信息和操作如何映射到空间 | 组件规范、空间组织、响应式布局 | 对齐、阅读、触控和键盘体验 |
| 5. 视觉与动效 | 如何建立清晰、有质感的表达 | Typography、Tokens、Motion | 视觉一致性、手感和性能 |
| 6. 肥鱼人格 | 如何让交互具备情绪与生命感 | Live2D、角色状态、场景 | 角色是否自然增强体验 |

这里的顺序体现依赖关系，并不意味着严格的瀑布开发。下游一旦暴露上游问题，就应当回去修改上游设计。
